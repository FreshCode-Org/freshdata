# FreshData Developer Advocacy & Distribution System

This directory contains developer advocacy, technical marketing, and organic community distribution assets for **FreshData**.

Our marketing philosophy is strictly **evidence-based and problem-first**:
* We never make unsubstantiated claims or market unreleased features.
* We never attack competitors or claim blanket superiority.
* We do not engage in star exchanges, paid stars, or engagement manipulation.
* We speak directly to developers and data engineers with working code, before/after evidence, and measurable benchmarks.

## Community Release & Content Cadence

Consistency matters more than volume. FreshData follows a sustainable 3-day weekly cadence:

```text
       MONDAY                       WEDNESDAY                     FRIDAY
┌──────────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐
│  Roadmap & Issues    │     │  Engineering Insight │     │ Community & Release  │
│  - Good First Issues │ ──► │  - 30s Video Demo    │ ──► │ - Release Notes      │
│  - Architecture goal │     │  - Failure case post │     │ - Contributor credit │
│  - RFC discussion    │     │  - Benchmark deep-   │     │ - Benchmark results  │
│                      │     │    dive              │     │                      │
└──────────────────────┘     └──────────────────────┘     └──────────────────────┘
```

* **Monday — Roadmap & Community Issues**: Highlight 2–3 active issues across Level 1 and Level 2 difficulty, inviting new contributors with direct links to `docs/contributing/first-contribution.md`.
* **Wednesday — Engineering Insights & Demos**: Share a technical nuance (e.g. why FreshData refuses to touch ID columns, or how DuckDB relation cleaning works) accompanied by runnable code.
* **Friday — Release & Contributor Spotlight**: Celebrate merged PRs, welcome first-time contributors by name, and publish new benchmark figures.
